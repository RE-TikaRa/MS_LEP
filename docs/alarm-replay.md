# 报警记录与回放

设备报警缓存保存报警前至报警时刻的诊断数据。原厂界面以序号排列十组采样，并将最后一组标作“报警时刻”。没有采样间隔字段，横轴不表示秒数。这里的缓存与 PC 上按设备 SN 保存的报警日志是两种数据：日志中的本地时间不是缓存采样的时间戳。

## 报文

读取缓存的请求沿用普通一字节长度帧。回复的命令字为 `0x0093`，其长度字段是**小端两字节**，包括记录数和记录数据，不包括帧头或帧尾。普通回复仍然只有一字节长度。

| 完整回复中的位置（从 0 起） | 内容 |
| --- | --- |
| 0 | 帧头 `24` |
| 1、2 | 命令 `93 00` |
| 3、4 | 载荷长度 |
| 5 | 载荷首字节：记录条数 |
| 6 起 | 每条记录 108 字节 |
| 末尾 | 帧尾 `2A` |

空载荷和只含零条数的载荷均表示空缓存。单字节 `45` 表示设备拒绝。三条记录的载荷长 325 字节，回复共 331 字节。长度与条数不匹配的内容不作为记录展示。

## 单条记录

按顺序读取类型（1 字节）、分类（1 字节）、功率、频率、脉宽、附加量一、附加量二。五组数据各有十个小端无符号 16 位数。结尾是两个小端 24 位数，分别为累计上电分钟数和出光分钟数。功率、频率和脉宽沿用原厂缓存显示的数值，不套用其他实时寄存器的换算。

| 类型 | 分类或通道 | 原厂换算 |
| --- | --- | --- |
| 0、1 | 传感器 1、2 温度 | `(raw - 200) / 10` °C |
| 2 | TEC；另有温度通道 | TEC 为 `raw / 10`；温度同上 |
| 3 | 无种子源：0 为 PD，其余为背光 | `raw / 100` V |
| 4 | 一级电流低：记录的是电压 | `raw / 100` V |
| 5 | 供电电压：0 为控制板，其余为驱动板 | `raw / 100` V |

未知类型保留类型码、分类码和两组附加原值。显示层不为未知量推定单位。

## 本机报警历史

GTK 客户端在 `$XDG_DATA_HOME/ms-lep/alarms/` 保存本机记录。未设置该变量时位于 `~/.local/share/ms-lep/alarms/`。文件名按设备 SN 编码。每行是 UTC 采集时间和四位十六进制报警状态字，以制表符分隔；历史页面按本地时区显示。

只有状态发生变化才追加一行，恢复状态也会保存。界面逐项列出相邻采样中从 0 变为 1 的报警位；首次连接时已存在的报警也会记录。保持同一报警状态重新连接会载入已有历史，不重复生成事件。两个客户端访问同一 SN 时会同步已追加的记录。无法确认的损坏或截断文件不会被覆盖，记录错误与设备通信错误单独显示。

时间来自上位机读到状态的时刻。断开连接期间发生、又在重连前恢复的报警，不能从轮询历史还原。本机状态日志与原厂 Windows CSV 是不同格式。

## 资料依据

- `LaserGUI-202607071/JPTLaserGUI.exe`：`SerialPortBaics.CheckReceiveDataComplete` 针对缓存使用两字节长度。`CommMessageInstance.SendMessage_AlarmCache` 向 `CommDataAnalysis.GetCustomAlarmCacheList` 传入整帧，因此原厂的索引 5 指整帧中的记录数，不是解帧后的载荷索引。
- `MainForm.ShowAlarmCacheDataToUI`、`GetAlarmClassifyName`、`GetAlarmValueString`：采样顺序、曲线、分类和单位换算。原厂的本地报警历史则来自 `ShowAlarmHistory` 读取的 `Log/<SN>/<月份>/Alarm`。
- `GUI User Manual_CN.pdf` 第 11 页、型号说明书 V1.0 的 PDF 第 25 页区分了报警记录与日志。`JPT-E-串口指令说明-20240401` 第 2、5、6 页描述的是状态和计数，没有给出扩展报警缓存的帧格式。
